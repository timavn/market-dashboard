# Complete portfolio cross-verification

Use this for “check every holding against the products,” “make sure the whole book is in line,” or a manual full-book audit. It is a current read of the existing reconciliation engine, not a new formal Portfolio Review or a semantic-search summary.

When the prompt supplies a server-owned manual verification capture ID, call `get_portfolio_verification_page` with that ID and no symbols, then follow every returned `nextCursor` until the complete summary/holding roster is read. Request needed evidence with the same capture ID and exact `symbols`, following its detail cursors. These pages preserve one immutable capture and never reacquire the book. The shared Sources table owns coverage and acquisition progress; do not repeat an Indexed research coverage table in that answer. Without a server-issued capture ID, call `get_portfolio_context` once with `include_research_verification: true` and `compact_research_verification: true`, then `get_process_context` only when explaining a portfolio rule that the code-produced review implication does not already explain. Use the verification's completeness, per-product coverage, archive manifest, all-holdings checks, classifications, original dates, and citations. Do not manually calculate replacements or claim every holding was checked from top-k search or a bounded review context.

Read the top-level `researchVerification` object. Its `complete` flag proves the stated scan scope, not universal alignment or delivery of every publication. Check `holdings`, `research`, `allHoldingsChecked`, and unresolved/unsupported diagnostics before any all-clear. If the verification is unavailable, partial, or its archive scan is incomplete, state that limitation once and explain the supported exceptions. No exception found is not proof everything is aligned. A verified empty book is different from a failed holdings refresh. Keep unknown, unsupported, derivative, and unvalued holdings in the check roster. A targeted `search_research`/`get_research_source` follow-up may explain a selected finding; it cannot establish scan completeness.

## Decode the compact capture

`representation: compact-columnar-v1` carries the complete manual check in one table. When `allHoldingsChecked.positionTable` is `data.positionTable`, use that table; otherwise use `allHoldingsChecked` itself. Map every row to its `columns`, verify `rowCount`, and preserve every row. Position names are `symbol` and `securityName` in the shared table. A cell such as `{"text": 3}` is the exact string at `researchVerification.textValues[3]`, not missing data. This table intentionally omits quantity, accounting, and quote fields; `weightPct` is the engine's independently verified sizing field and must not be recalculated. `positionId` and captured contract/category/expiration details keep distinct holdings separate.

The table already carries each holding's exact primary `reading`, `reviewAction`, `publishedAt`, `sourceAction`, eligibility, and classification. Each holding's `evidenceIds` contains zero-based row indexes in `evidenceTable`, which retains independently published latest Trade/Trend and current material actions or conflicts. Decode its columns and text references likewise. Each holding's `sourceRefs` contains zero-based row indexes in `citationTable`; decode those columns to obtain exact tool-issued citation IDs, source links, and publication dates. An evidence row's `sourceRefs` may instead contain exact citation ID strings whose secondary source metadata is deferred; do not invent a citation or pretend that metadata was opened.

`detailScope` states how much secondary dated evidence and source/accounting detail was deferred from model context. This does not reduce the engine's stated archive scan or full holding roster, and does not prove delivery of all products. Explain the supported findings from the original capture. Do not loop through every research product, re-run the full capture, try to open a spillover path with `skill_view`, or run searches merely to confirm that a missing signal is absent. If an exact selected finding needs more evidence, use `get_portfolio_verification_page` with the original capture ID and `symbols: ["EXACT_TICKER"]`; it returns detail-only pages and full source metadata without duplicating the full book. Archive-generated citations may resolve through their direct source link rather than the local index's `get_research_source`; a not-found index response is not proof the publication is missing.

## Present the check

Keep **Verification scope** compact: retain the captured account, observation date, complete holding count, Long/Short counts, and current-book description. For a server-owned manual capture, the shared Sources table already presents coverage; omit **Indexed research coverage** from the narrative. When no server-owned capture was issued, present that legacy coverage as a `Product | Latest publication` table using the returned original publication dates. Do not add Security metadata or Process context paragraphs, sizing-policy/canonical-version diagnostics, or descriptions of the internal identity lookup. Explain an applicable rule beside its evidenced exception instead.

Keep narrative to the material findings and table cells to short supported phrases. Preserve every requested holding, exact partial/full source action, proxy qualifier, code-produced weight when verified, and original evidence date; do not repeat the same explanation across scope, watch, alignment, and sequence sections.

Omit standalone boilerplate paragraphs explaining the Trade-break exit rule, Cover-SOME versus generic Cover headlines for CHH/VFC/JACK, or latest-publication dates versus delivery; retain precise dated action/table evidence and apply the underlying rules and delivery checks internally.

Follow with four compact sections only when they contain useful evidence:

1. **Highest-priority realignment:** current eligible direct Trade conflicts and applicable Trend rules, then explicit source actions. Use exactly `Ticker | Security | Held side | Action | Source`. Keep Action to the concise evidenced instruction, such as `Cover some` or `Sell some`; preserve full `Cover`, `Sell`, or `Exit` only when that full action is explicitly supported. The exact report's partial body instruction takes precedence over a generic Cover/Sell headline. Do not add a Description, Review implication, or separate date column, or append requalification, Trade/Trend-priority, absence-of-signal, or other rule boilerplate to Action. Source names the exact captured product and its original action publication date, with that publication's tool-issued citation. Match it to the action evidence and captured citation metadata, never a newer confirmation, monitor, scan, or holdings-refresh date. Keep proxy qualifications attached to the applicable source. If source metadata for a selected action is deferred, use the scoped evidence read above rather than guessing a product or date. Keep a dated archived source action distinct from a current eligible portfolio action; the shorter cell must not manufacture current eligibility.
2. **Watch list:** ambiguous readings, incomplete support, unsupported instruments, and dated requalification items. Present each item as a separate paragraph, without bullets. Keep unknown separate from misaligned.
3. **What is already aligned:** concise supported alignment. Include an `All holdings checked` securities table for this explicitly complete-book request, beginning `Ticker | Security | Held side`, preserving the verification's exact source reading, implication, and date. Put event contracts in a separate compact table immediately underneath it, as described below; preserve every returned holding across the two tables. Show code-produced weights only when verified. If the fresh book is unavailable, say so; do not construct an unnamed roster or revive prior holdings.
4. **Recommended sequence:** the projection's evidenced order. Do not invent trades, target sizes, executable prices, or priorities based on missing values.

The Security column contains the actual company or fund name from the captured `securityName`/`security` field. The manual capture supplements absent broker names through the same exact-ticker, provider-verified descriptive identity service used by Portfolio. Preserve a supplied captured name, and keep descriptive identity separate from research, holdings and quotes. Never repeat the ticker, `STK`, or `name unavailable` in Security; use an em dash only if no verified name was obtained. Keep tickers blue and company/fund names semibold at the report body's font size through the shared report renderer. In Highest-priority realignment, keep the exact product, original publication date, and citation in each row's Source column. Put other source citations at the bottom of their supported section, using one plain bracket pair per reference and no extra bold brackets.

Use `Held side` as the securities column header. The separate `Event contracts checked` table begins `Contract | YES/NO`; retain each holding's exact captured contract identity, threshold/outcome, expiration, and held YES or NO side, followed by its supported reading, implication, date, and sources. Distinct KXCPIYOY thresholds and YES/NO holdings remain distinct rows; do not shorten them all to the root ticker or merge them into a securities row. Preserve the captured all-position count and original evidence dates across both tables; changing the presentation does not change verification scope.

Preserve Sell some versus Sell/Exit, Cover some versus full cover, Trade versus Trend, rank/list membership versus direction, and direct versus proxy signals. Read the exact action report's body and structured scope when a generic headline omits a partial instruction; its explicit partial action takes precedence over that headline. Later omission never erases dated research; an explicit later re-add or affirmative membership in a later complete publisher book can supersede a same-product removal. Archived actions stay dated and cannot manufacture a current exit signal. Preserve independently valid research fields when another source value is questionable, retaining the original discrepancy and its source. Keep Highest-priority realignment's product, original publication date, and citation in its Source column; use compact Sources footers for other source citations. Keep detailed delivery diagnostics in source detail rather than the main answer.
